# 企业级 VLA 训练平台 · v1.0 目标架构

> 本文是 v1.0 的总设计。所有并行 Agent 以本文为唯一契约。
> 上一版（v0.9.1）已有能力：PyTorchJob 提交、Kueue 排队、按用户配额、LDAP 鉴权、
> 参数模板、日志/事件/取消/clone。**本版的核心增量是数据集管理与「一键训练」体验。**

## 0. 用户旅程（北极星）

```
打开网页
   ↓
看到「数据集」列表（已自动扫描好，显示 episode 数/时长/相机/动作维度/是否可用）
   ↓
点一个可用的数据集 → 「开始训练」
   ↓
弹出最简表单：只填【训练配方】（默认已选好）+【任务名】（自动生成）
   ↓
点「加入队列」
   ↓
跳转到任务页：排队位置、预计等待、开始后实时 loss 曲线 + 日志
```

**关键指标**：从打开页面到任务进队列，操作步数 ≤ 3，必填字段 ≤ 2。

## 1. 核心理念：三层参数模型

这是本次设计的核心。把参数分成三层，用「谁能改」来区分：

| 层 | 名称 | 谁定 | 用户能否改 | 存放位置 |
|---|---|---|---|---|
| L1 | **Recipe（训练配方）** | 平台管理员 | 只能选择，不能改 | `recipes/*.yaml` |
| L2 | **常用参数** | 配方作者声明 | 可以改，默认折叠在「参数」里 | 配方里的 `params` + 模板 |
| L3 | **高级参数** | 配方作者声明 | 可以改，默认折叠在最底层 | 同上，`advanced: true` |

**普通用户只操作 L1**（选配方）。L2/L3 默认收起，展开才看到。

一个「配方」= 镜像 + 参数模板 + 数据集类型 + 默认超参 + 描述，例如：

```yaml
# recipes/smolvla-finetune.yaml
id: smolvla-finetune
name: SmolVLA 微调
description: 从 SmolVLA 基座权重微调，适合单卡 4090 的抓取类任务
image: vla-smolvla:v1
dataset_formats: [lerobot-v3, lerobot-v2]
params_template: vla-smolvla:v1        # 引用已登记的参数模板，也可内联
defaults:
  steps: 2000
  batch_size: 8
  save_freq: 500
entrypoint: python /app/train.py
gpu_count: 1
estimated_vram_gb: 24
```

## 2. 数据集管理（最关键的增量）

### 2.1 数据集来源

数据集放在宿主机 `/data/vla-platform/datasets/<name>/`，每个子目录是一个数据集。
平台**自动扫描**这个目录，无需手工登记。

扫描产生的元数据存在 SQLite，扫描本身是**异步 + 可重入**的：

- 启动时扫描一次
- `POST /api/v1/datasets/scan` 手动触发（管理员）
- 页面进入数据集列表时，如果发现「目录存在但库里没有」或「mtime 变了」，自动排队扫描

### 2.2 扫描内容（分两档）

**浅扫描（< 2 秒，列表页用）**：只读 `meta/info.json` + 目录结构。

**深扫描（后台执行，详情页用）**：抽样读 parquet 校验列、读 videos 校验可解码。

必须采集的元数据见 `DATASET-SCAN-SPEC.md`（另一个 Agent 产出，本文只定义接口）。

### 2.3 数据集对象

```json
{
  "id": "pick1028",
  "name": "pick1028",
  "path": "/datasets/pick1028",
  "format": "lerobot-v3.0",
  "status": "ready",
  "size_bytes": 645922816,
  "episodes": 143,
  "frames": 60470,
  "fps": 30,
  "tasks": ["pick up the object"],
  "robot_type": "dual_arm_mobile",
  "cameras": ["observation.images.camera1", "observation.images.camera2", "observation.images.camera3"],
  "image_size": [480, 640],
  "state_dim": 14,
  "action_dim": 14,
  "action_names": ["arm1_joint_1.cmd", "..."],
  "scanned_at": "2026-11-10T00:00:00Z",
  "scan_depth": "deep",
  "issues": [
    {"level": "warning", "code": "fps_mismatch", "message": "..."}
  ]
}
```

`status` 取值：`scanning` / `ready` / `warning` / `unusable` / `error`

### 2.4 数据集接口

```
GET  /api/v1/datasets                 列出所有数据集（含浅扫描结果）
GET  /api/v1/datasets/{id}            单个数据集详情（含深扫描与 issues）
POST /api/v1/datasets/scan            触发扫描（admin），body: {"id": "...", "deep": true}
GET  /api/v1/datasets/{id}/preview    预览：随机几个 episode 的首帧/动作统计
```

## 3. 训练配方（Recipe）

### 3.1 存储

`recipes/` 目录下的 YAML 文件，随镜像打进容器（`/app/recipes/`）。管理员改配方 = 改文件 + 重新部署。
**v1.0 不做网页端编辑配方**（降低复杂度），但提供只读浏览。

### 3.2 接口

```
GET /api/v1/recipes                   列出所有配方（含参数模板展开后的字段）
GET /api/v1/recipes/{id}              单个配方详情
```

### 3.3 数据集与配方的兼容性

提交时校验：数据集的 `format` 是否在配方的 `dataset_formats` 里。
不兼容 → 422，提示「配方 X 不支持数据集格式 Y，可用配方：Z」。

## 4. 一键提交

### 4.1 新接口（推荐路径）

```
POST /api/v1/runs
{
  "recipe_id": "smolvla-finetune",
  "dataset_id": "pick1028",
  "name": "smolvla-pick1028-001",     // 可选，省略则自动生成
  "overrides": {"steps": 1000},        // 可选，L2/L3 参数覆盖
  "priority": "normal"
}
```

服务端做的事情：
1. 校验配方存在、数据集状态可用、格式兼容
2. 生成任务名（省略时）：`<recipe-short>-<dataset>-<3位序号>`
3. 用配方的 entrypoint + 参数模板 + defaults + overrides 渲染命令
4. 把数据集路径注入为 `DATASET_ROOT=/datasets/<id>` 环境变量
5. 走既有的 PyTorchJob 提交路径（配额、Kueue、owner 全部复用）
6. 返回完整 Job 对象

**这条路径必须复用既有的 `PlatformService.submit`**，不要另起一套。

### 4.2 兼容性

既有的 `POST /api/v1/jobs` 保持完全不变（CLI、老用户、手工提交继续可用）。

## 5. 「排队位置」与可观测性

### 5.1 队列位置

Job 响应新增字段：

```json
{
  "queue_position": 2,
  "queue_eta_seconds": 1800,
  "queue_state": "queued"
}
```

- `queue_position`：在 Kueue 里的排队序位（从 1 开始），非排队时为 null
- `queue_eta_seconds`：基于「当前运行任务的平均剩余时间」估算，可粗，但要**说明是估算**
- `queue_state`：`queued` / `admitted` / `running` / `finished`

### 5.2 训练指标（loss 曲线）

训练容器把指标写到一个约定位置：容器内 `/checkpoints/<job>/metrics.jsonl`，每行一条：

```json
{"step": 100, "loss": 0.0234, "lr": 1e-4, "epoch": 0.12, "timestamp": "2026-01-01T00:00:00Z"}
```

平台接口：

```
GET /api/v1/jobs/{name}/metrics?limit=2000
-> {"name": "...", "items": [...], "step": 100, "total_steps": 2000}
```

后端通过**读宿主机上的文件**实现（`/data/vla-platform/checkpoints/<job>/metrics.jsonl`），
因为 checkpoint 目录已经挂载给 Web Pod。要注意：
- 文件可能不存在（老任务）→ 返回空 items，不报错
- 文件可能很大 → 只读末尾 N 行，且 limit 上限 5000
- 正在写入 → 最后一行可能不完整，要跳过解析失败的行

## 6. 页面结构

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | **快速开始** | 数据集卡片网格 + 选配方 → 一键开始。**这是新的首页** |
| `/datasets` | 数据集 | 列表 + 详情（含元数据、issues、预览） |
| `/recipes` | 训练配方 | 只读浏览配方及其参数 |
| `/jobs` | 任务 | 现有页面，增加排队位置与 ETA 列 |
| `/jobs/:name` | 任务详情 | 增加 loss 曲线图 |
| `/queues` | 队列 | 现有 |
| `/users` | 用户与配额 | 现有，仅 admin |
| `/advanced/submit` | 高级提交 | **原 `/submit` 页面**，保留给需要全字段控制的用户 |

`/submit` 保留为别名重定向到 `/advanced/submit`，避免老链接失效。

## 7. 后端模块划分（新的）

```

├── datasets/
│   ├── scanner.py        # 扫描 + 元数据采集（浅/深）

│   └── models.py
├── services/

└── api/routes_datasets.py, routes_recipes.py, routes_runs.py
```

新增表：

```sql
CREATE TABLE IF NOT EXISTS datasets (
    id TEXT PRIMARY KEY,
    meta_json TEXT NOT NULL,
    dir_mtime REAL NOT NULL,
    scanned_at TEXT NOT NULL,
    scan_depth TEXT NOT NULL
);
```

## 8. 分期计划

| 阶段 | 内容 | 验收 |

| P1 | 数据集扫描 + 元数据接口 | 能列出 pick1028 的 episodes/frames/相机/维度 |
